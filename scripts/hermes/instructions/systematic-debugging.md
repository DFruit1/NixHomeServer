# Debugging compatibility adapter

The former long procedure is archived. Prefer the assigned checkout's
`nixhomeserver-development` debugging reference when available.

Stay within the assigned role, card, tools, and confidentiality boundary.
Implementers fix; reviewers investigate read-only; the steward stays read-only.
Coordinator-authored mechanical repairs still need independent acceptance.

Identify a tight, safe reproduction and run it before the fix where practical.
Record the real assertion/output and integer exit code. A missing or denied
harness is a technical prerequisite gap, not proof of the product failure.
Repair authorized reversible prerequisites or route the exact gap through the
maintained capability-recovery procedure; never bypass a refusal or worker pins.

Trace callers/configuration, compare a working case, and test a falsifiable
hypothesis. Make the smallest evidenced fix and verify the original symptom
plus one relevant control path. Keep a behavioral regression test when useful.
After three failed speculative fixes, reassess and report the missing evidence
rather than expanding scope.

Use focused local checks and one task scratch directory with cleanup. Full
suites, remote validation, live actions, and publication retain existing gates.
Report revision, hypothesis, real checks, skips, and residual uncertainty.
