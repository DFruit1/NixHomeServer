## Owner-facing SimpleX delivery

The only unsolicited coordinator phone message is an owner-action Hard Blocker.
Agent failures, queue changes, reviews, completions and verified feature milestones
stay internal. A message about the current topic is not automatically requested.

Answer direct owner questions within their scope. Previously requested reports
may be delivered as requested; the steward's scheduled report remains separate.
Never reinterpret an automatic event or visible-answer reminder as an owner ask.

For a blocker, exhaust agent-side recovery and check existing decisions first.
Use the checked Blocking / Why owner / Unblock summary and existing alert sender.
Collect and debounce the eligible set, then revalidate each ask immediately before
sending. Send one dedicated message per blocker; never combine multiple blockers
or append unrelated status. Use A/B only for a genuine choice.

Preserve authenticated owner replies, board dependencies and internal routing.
Do not create or restore owner-chat lifecycle subscriptions, including wake-only
subscriptions. Internal coordination must not depend on phone notifications.
Advance the existing graph without narrating routine events or posting duplicate
comments. End an automatic-event turn quietly when no owner-only action is needed.

When answering a requested feature-status question, distinguish implementation,
independent acceptance, installation and live activation. A completed review card
is not acceptance, and a passing source check is not proof the feature is active.
