# Design System

Living record of this repo's frontend design decisions. Maintained by the
`frontend-design` skill workflow (`.agents/skills/frontend-design/SKILL.md`).

Rules for keeping this file useful:

- **Tokens and existing components first.** Before introducing new spacing,
  colours, radii, typography, shadows or components, check the target app's
  styles file and this page. Record anything deliberate here so future agents
  (and the Impeccable detectors) treat it as an intentional project choice, not
  drift.
- **No invented UI.** Metrics, badges, helper text, cards or dashboard panels
  only when they materially help a task or decision (see the anti-slop rules in
  the frontend-design skill).
- **Detector exceptions.** When a deliberate choice trips an Impeccable detector
  rule, add a narrowly scoped exception in `.impeccable/config.json`
  (`detector.ignoreRules` / `ignoreFiles` / `ignoreValues`) and note it in the
  decisions ledger below. Do not change the design to silence a detector.

Transfer feedback and failures render inside the dialog, where a modal page toast would be hidden behind the backdrop. | — |

| File Sync's server owns the folder walk, the hashing and the diff, and keeps a manifest per folder so a steady-state estimate costs one directory walk and no file reads | filesync (`filesync-api/src/manifest.rs`, `filesync-api/src/main.rs`, `src-tauri/src/lib.rs`, `BackgroundSync.kt`, `src/main.ts`) | The phone used to walk the tree itself — one HTTP request per directory with `hashes=true` — and the server re-read and re-hashed every library on each estimate, while the app asked for an estimate on sign-in and after every enable, remove, sync and address change. On Android the listing hashed every *local* file too, so a refresh read the whole device copy as well. Now the server keeps a manifest per (account, root, path) of each file's path, size, mtime and hash-on-demand, and the device sends only `(path, size, mtime)` for what it holds. Files whose metadata agrees are identical without any read; the few that disagree come back as `needsHash` and only those are hashed, on the device and then on the server, once each and cached. A transfer still loads the full remote tree, because deciding what to move needs every hash — but only when it is actually moving something. Walks are bounded by depth, entry count and wall time, and a tripped bound is reported as `truncated` so a partial sum is never presented as a total. Hash reuse keys on size and mtime, the same trade every incremental sync tool makes, and a file that cannot be read is reported as unreadable rather than silently counted as unchanged. | — |

Media health defaults to every visible library and automatically inspects all bounded API pages, with at most three libraries scanning concurrently. Results use effective titles, grouped field comparisons, labelled source alternatives, and collapsible file paths. Each result header pairs the library's media-kind symbol with an oversized title (italic when it falls back to a filename) over a faded artwork band, and each issue names one recommended online source plus its setup state, with the remaining candidates behind an "Alternative Sources" dialog. A compared issue lays out four columns on wide screens — the reason, the current value, the proposed value, and a prose paragraph explaining where the proposal came from plus the check that resolves any ambiguity; between 720px and 960px the reason and the prose take their own full-width rows above the two value columns, and on phones every column stacks. An unset value renders as italic *Not set*. Audio results group by album (parent folder) into one article per album with per-file review links, so a 30-file audiobook never renders 30 separate warnings; grouped problems carry their affected files inline. Filename-derived guesses remain fallback metadata but do not create conflicts with actual metadata sources. Scan failures preserve other libraries' results and mark totals as incomplete.

The library category controls reuse sidebar symbols in one evenly spaced row. Dual trees use larger centered symbols; selecting a personal or shared item narrows its tree to 45% of the available desktop columns and gives the detail column the full height beside it. Labels appear below icons on hover or keyboard focus and remain visible on phones. Folder metadata starts with Basics/Advanced and the draft action on one row; detailed source inspection lives under Advanced. Audiobook, podcast, and music folders add a Track order table reusing the metadata-comparison table: one row per file with filename, tag, playlist, and effective positions, plus one grouped warning per problem with affected files. Library search is deliberately split. The library toolbar filters the currently loaded titles and filenames client-side and sends no query anywhere; full metadata and full-text discovery stays in the Search app and is reached through an optional "Advanced search" link that renders only when the deployment registers the `search` capability. Library reads are always served from the catalog cache and never walk the filesystem: the toolbar "Refresh" runs one cooldown-limited scan of the active category's roots, and a background scanner reconciles due roots on an adaptive backoff (15 then 30, 45, and 60 minutes, then hourly to a 24-hour ceiling, resetting on change). The Activity view lists the durable mutation queue as rows with a state badge and owner-only Retry/Cancel actions, and states read-only mode inline.

### Media playback continuity

The music player keeps one audio element mounted across same-app navigation, with
a compact player above the phone navigation on other pages. The PiP icon left of
the sleep timer toggles this behavior; it defaults on and remembers the choice.
Turning it off pauses music when leaving Music. Native links, modified clicks,
external links and library selection history retain their normal behavior. Video
selection never autoplays or takes the music media session; actual playback owns
the media session and pauses other media.

Now-playing artwork uses 4:3 when the original is at least that wide, otherwise
1:1. The Up next card below the main player starts its candidate when clicked;
its separate skip control removes only that upcoming candidate. The same queue
preview drives Next and natural track completion, preserving shuffle/repeat/stop.
Library Refresh is a normal right-aligned footer action beside Advanced search,
sharing its typography. Activity remains addressable but is hidden from navigation.
