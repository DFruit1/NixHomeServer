# Design System

Living record of this repo's frontend design decisions. Maintained by the
`frontend-design` skill workflow (`.agents/skills/frontend-design/SKILL.md`).

Rules for keeping this file useful:

- **Tokens and existing components first.** Before introducing new spacing,
  colours, radii, typography, shadows or components, check the target app's
  styles file and this page. Record anything deliberate here so future agents
  (and the Impeccable detectors) treat it as an intentional project choice, not
  drift.
- **No invented UI.** Metrics, badges, helper text, cards or dashboard panels
  only when they materially help a task or decision (see the anti-slop rules in
  the frontend-design skill).
- **Detector exceptions.** When a deliberate choice trips an Impeccable detector
  rule, add a narrowly scoped exception in `.impeccable/config.json`
  (`detector.ignoreRules` / `ignoreFiles` / `ignoreValues`) and note it in the
  decisions ledger below. Do not change the design to silence a detector.

### Media playback continuity

The music player keeps one audio element mounted across same-app navigation, with
a compact player above the phone navigation on other pages. "Keep playing on
other pages" in Playback options toggles this behavior; it defaults on and
remembers the choice.
Turning it off pauses music when leaving Music. Native links, modified clicks,
external links and library selection history retain their normal behavior. Video
selection never autoplays or takes the music media session; actual playback owns
the media session and pauses other media.

Now-playing artwork uses 4:3 when the original is at least that wide, otherwise
1:1. The Up next card below the main player starts its candidate when clicked;
its separate skip control removes only that upcoming candidate. The same queue
preview drives Next and natural track completion, preserving shuffle/repeat/stop.
Library Refresh is a normal right-aligned footer action beside Advanced search,
sharing its typography. Activity is in the navigation as "Recent changes" (restored
2026-11-17 at owner request; it was hidden without a recorded reason).

Media health track-sequence warnings offer an inline “Renumber tracks…” editor.
It defaults to effective playback order and offers filename/playlist order plus
keyboard-accessible up/down controls. One guarded album plan previews and writes
track 1–N, track total N and disc 1/1 into every audio file, matching zero-padded
filenames, M3U/M3U8/PLS/XSPF playlists and a `track-order.json` sidecar. Exact
server filename and embedded-number previews, errors and completion guidance
scroll into view below the album banner. Original audio is archived with a
non-playable `.backup` suffix; existing ordering sidecars are archived before
replacement and file-specific metadata follows renames. Unsupported or incomplete
albums block preparation. Activity owns execution/retry; players need a refresh
after completion and can still override order through shuffle or manual queues.

Search result actions show Show transcript (for linked media/transcript files),
Copy link, then Details, with the same quiet text hierarchy. Transcript links
open Media Manager's searchable dialogue view without starting playback. Folder
results offer their individual recordings; absent timing falls back to readable
text, and missing transcripts report availability in place. The reader uses
page scrolling so the final line remains reachable on phones and desktops.

Metadata Basics separates the read-only folder identity (YouTube channel, audiobook, album or collection) from its media contents. A direct single-track folder reads Music track; artwork, subtitles and metadata sidecars do not add to the server-reported media count. People fields use one name per line to preserve commas within names; genres remain comma-separated. Folder labels are inferred from the producer path, server media type and available series metadata; an unconfirmed grouping stays a collection.
