# MISSION.md Format

`MISSION.md` lives at the teaching-workspace root. It records why the user is
learning the topic. Every lesson should trace back to it.

```md
# Mission: {Topic}

## Why
{The concrete real-world outcome the learner wants.}

## Success looks like
- {A specific, observable capability}
- {Another specific capability}

## Constraints
- {Time, budget, prior commitments, or learning preferences}

## Out of scope
- {Adjacent topics intentionally deferred}
```

Keep one mission per workspace, make it concrete, and keep it short. Interview
the user when the motivation is too vague to guide teaching. Revise the file
when reality changes rather than allowing a stale mission to steer future
lessons.
